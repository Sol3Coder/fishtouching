# novel-tui —— 独立的小说阅读器

一个终端里的阅读器（ratatui TUI）。**它能读真的网络小说** ——
直接吃 legado（Android「阅读」）的书源 JSON，不用转换，
书源里的 JavaScript 也是真跑的（内置 QuickJS）。

```
 演示书架 · 《夜色渐浓》 示例作者  第 1 / 3 章  书源 3/3        上次搜索 “斗破苍穹”
 书架 › 目录 · 夜色渐浓 › 阅读 · 第 1 / 3 章    Esc 返回上一层
┌ 夜色渐浓 第 1 / 3 章 ─────────────────────────────────────────────┐
│推开门                                                            │
│                                                                  │
│他推开门，楼道里的声控灯亮了一下，又灭了。                        │
│                                                                  │
│外面在下雨。雨点打在铁皮雨棚上，像有人在楼上不停地挪椅子。        │
└──────────────────────────────────────────────────────────────────┘
 第 1 / 3 章                                          ⟳ 没有后台任务
 ↑↓ PgUp/PgDn 滚动   n p 上下章   g 跳章   Esc 回目录   ? 帮助
```

**五个屏是平级的**，同一时刻只显示一个，但谁也不在谁「里面」——

```
 1 书架   2 搜索   3 目录   4 阅读   5 书源        夜色渐浓 · 3 章
```

第二行是**标签栏**：五个屏都列出来，当前那个反显，**数字键就写在名字前面**，
所以「按几能跳过去」不用另外记。

- **数字键直接跳屏** —— 这是「独立进入」最直白的表达，没有「先进书架再进目录」
- **`Enter` 在有意义的地方切到另一屏**：打开书 → 目录，选章 → 阅读。
  那是「跳到另一个屏」，不是「进入下一层」
- **`Esc` = 回书架**（固定的「家」），不是「退回上一层」—— 平级就没有上一层
- **`q` 哪一屏都能退出**；搜索框有焦点时它是**文本**

早先做过层级版（书架 › 目录 › 阅读，Esc 逐层退回，面包屑画整条路径）。
那样「我在哪一层」和「Esc 会去哪」都得靠面包屑解释；平级之后这两个问题
都不存在了 —— 面包屑也就换成了标签栏。

阅读页 `.novel/reader.novel` 是一份**能读的 TypeScript 文件**：
小说正文全部在 `//` 注释里，其余是随机生成的示例代码。

## 跑起来

```bash
cargo build -p novel-tui

# 用书源（默认找 .novel/sources.json）
cargo run -p novel-tui
cargo run -p novel-tui -- --sources 某个书源集合.json

# 不带书源也能跑：内置演示书库
cargo run -p novel-tui -- --offline
```

仓库里 `.novel/sources.json` 已经放了 3 个**实测能用**的书源
（鬼吹灯 / 抖音小说 / 77读书）。想换更多，见下面「书源」。

## 书源

格式就是 legado 的导出格式 —— `bookSourceName` / `searchUrl` / `ruleSearch`
那一套，**可以直接用现成的书源集合**（比如各种「阅读」书源分享站导出的 JSON）。
`crates/novel-core/tests/fixtures/sources-runnable.json` 里有一份筛好的
596 个（每个域名一条）。

### 支持到什么程度

| 能力 | 状态 |
|---|---|
| 默认 HTML 方言（`class.x@tag.a.0@text`） | ✅ |
| `tag.` `class.` `id.` `text.` `children.` 步骤 | ✅ |
| 索引 `.0` / `!0:1:2` / `[0,-1,3:5]` / `[-1:0]` | ✅ |
| 取值器 `@text` `@textNodes` `@ownText` `@html` `@all` `@属性名` | ✅ |
| `##` 替换（两段 / 三段 / 四段） | ✅ |
| JSoup 私有选择器 `:eq` `:lt` `:gt` `:contains` `:matches` `:not` `:has` `:nth-child` … | ✅ |
| `@css:` 前缀 | ✅ |
| `&&` / `\|\|` / `%%` 组合（按平衡组切分，`[]` 里的不算分隔符） | ✅ |
| URL 两段式 `url,{"method":"POST","body":…,"charset":"gbk"}` | ✅ |
| GSON 那种单引号 JSON 选项（123 个源这么写） | ✅ |
| `{{page}}` `{{key}}` `{{(page-1)*50}}` `{{page*-1+11}}` `Math.round(new Date()/1000)` | ✅ |
| GBK/GB2312/Big5 解码 | ✅ |
| 相对 URL、重定向后的基准、`javascript:` 丢弃 | ✅ |
| `tocUrl` / `nextTocUrl` / `nextContentUrl` 分页 | ✅ |
| **`@js:` / `<js>` / `{{js}}`（内置 QuickJS）** | ✅ |
| `{{@@class.x@text}}` 这种「方括号里是规则」 | ✅ |
| `java.ajax` / `getString` / `getElement(s)` / `put` / `get` | ✅ |
| `java.md5Encode` / `sha1` / `sha256` / `base64*` / `timeFormat` / `encodeURI` | ✅ |
| `java.lang.*` / `java.util.Base64` / `java.security.MessageDigest` | ✅ |
| 元素对象的 `length` / `size()` / `get(i)` / `select()` / `attr()` / `text()` / `toArray()` | ✅ |
| `@webjs:`（要真浏览器） | ❌ 明确报错 |
| XPath（`/`、`@xpath:`） | ❌ 明确报错 |
| JSON 路径（`$.`、`@json:`） | ❌ 明确报错 |
| `javax.crypto` 等 JVM 类互操作（AES 之类） | ❌ 明确报出类名 |

**不支持的一律报错，不猜。** 猜错的表现是「静默抓到空内容或者广告」，
比报错难查得多。没实现的 Java 类会报出**它自己的名字**
（`java.aesBase64DecodeToString 未实现`），而不是含糊的
「cannot read property of undefined」。

### JS 是怎么接进来的

| | |
|---|---|
| 引擎 | **QuickJS**（`rquickjs`），不是纯 Rust 的 `boa_engine` |
| 为什么 | 依赖差 6 倍：boa 124 个（`icu_*` 那一大坨），rquickjs 21 个；release 只多 1.3 MB |
| 代价 | 需要一个 C 编译器（`rquickjs-sys` 自己编 vendored QuickJS）。**不开 `bindgen`**，那会额外要 libclang |
| 分层 | Rust 只暴露十几个签名极简的原语（`__ajax` / `__rule` / `__md5` …），legado 那套 `java.*` 的形状写在 200 行 JS prelude 里 |
| 为什么这么分 | Rust 闭包直接暴露成 JS 函数要和 `FromParam`/`IntoJsFunc` 的生命周期搏斗；而元素对象有十几个方法，在 JS 里写是 30 行、在 Rust 里写是 300 行 |
| 线程 | `Runtime`/`Context` 都不是 `Send`，所以 `Js` 在每个任务里现建现弃，worker 线程栈给到 8 MB（QuickJS 的栈上限设 1 MB，比原生栈小才不会把进程带崩） |

### 那到底能读几本书

拿 3907 个真实书源筛了一遍（脚本在下面）：

## 按键

`q` 和 `Ctrl-C` 都是**全局退出**，哪一屏都行。`1`-`5` 是全局跳屏。

除此之外的字母键都是**本屏**的 —— 不做全局跳转，否则在搜索框里打字会误触发。
关键取舍：**搜索框有焦点时，可打印字符一律是文本**（包括 `q`、数字、`/`、`b`），
所以「在搜索框里打小说名带个 q 就退出」不会发生；`Tab` 交出焦点之后它们才是命令。

**书架**（根屏）

| 键 | 作用 |
|---|---|
| `↑` `↓` / `j` `k` | 选书 |
| `Enter` | 进目录（并定位到上次读到的那一章）|
| `}` / `{` | 下一本 / 上一本（按最近阅读倒序）|
| `/` 或 `s` | 进搜索 |
| `S` | 进书源 |
| `d` | 把这本书移出书架（**不删阅读记录**）|

**搜索**（关键字框是常驻焦点，不是临时模式）

| 键 | 作用 |
|---|---|
| 打字 | 改关键字（这一个框里**所有**可打印字符都是文本）|
| `Enter` | 搜索 |
| `Tab` | 在 关键字框 / 结果列表 之间切 |
| `↑` `↓` | 选结果 |

| `Esc` | 回书架（结果和关键字都留着，不重搜）|

## JSON 书源（JSON 路径）

真书源里有一大批是**纯 JSON API**（自己的 app 接口），规则写 `$.data.list[*]`
而不是选择器。这一块现在支持了。

**范围是量出来的，不是照着 JsonPath 规范做的。** 拿 3907 个真书源统计 7756 条
JSON 路径，形状分布是 `$.K` 4359、`$.K.K` 729、`$..K` 307、`$..K[*]` 248、
`$.K[*]` 200、`$.[*]` 44、`$.K.*` 39；过滤器只有 59 条，**全是**
`[?(@.key)]` / `==` / `!=` 三种；切片只有 19 条，**全是** `[1:]` / `[:10]`。
所以实现的就是这些，剩下的一律**报错**（多下标并集 `[0,1]`、脚本下标
`[(@.length-1)]`、比较运算符 `>`）：猜错的表现是静默取到空内容或别的东西，
比报错难查得多。

贴着 legado 的三条语义（都是读它的源码定的，不是猜的）：

- **定路径不隐式展开数组。** `$.a.b` 里 `a` 是数组时结果是空 —— Jayway 就是
  这样，真书源也都明写 `[*]`。
- **元素列表 = `read<ArrayList>`。** 不定路径 → 匹配结果就是列表；定路径指着
  **数组** → 那个数组自己就是列表（`$.data` 这种写法用了 49 次）；定路径指着
  标量 → 转 List 失败 → 空。
- **正文是 JSON 时，所有规则都当 JSON 路径解**（legado 的 `isJSON` 标志）。
  所以真有 `chapterList: "data"` 这种**不带 `$.` 的裸键名**。要写选择器得用
  `@@` / `@css:` 逃出来。

`@put:{name:取值}` 也做了（取值部分是**规则**，legado 是
`put(key, getString(value))`）—— 17k 那种「搜索拿到 id、再拼目录 URL」的
API 源全靠它。注意是**后写的赢**：一条 `bookList` 跑完，变量里留的是最后一条
结果的值。

顺手修掉的两条（都是「静默取空」那一类，比报错难查得多）：

- **一个字面地址被当成选择器查。** `bookUrl: "http://api.x/book/{{$.id}}/info"`
  展开之后就是个 URL，没有选择器可套。legado 会拿它去查 CSS、最后取到空
  （它自己的 bug）；现在按作者的意图返回地址本身。
- **内嵌规则没跟着当前元素。** `{{$.id}}` 里的 `$.id` 是**这个搜索结果元素**
  的 id，不是整篇文档的。原来写死 `None`，于是永远取到空 ——
  表现是「搜索有结果，点进去打不开」。
- **一个写坏的可选字段会干掉整次搜索。** 简介/封面取不到就留空，
  不能让全部结果跟着消失。书名和链接仍然是必需的。

## XPath 书源

同样是**先量再写**。691 条真 XPath 表达式里：

* **轴只有两个**：`following-sibling::` 39 次、`preceding-sibling::` 3 次。
  没有 `ancestor::`、`following::` 这些。
* **谓词只有四种形状**：`[@a='v']` 366、`[n]` 148、`[函数()='v']` 41、
  `[子元素名]` 15，外加 10 条 `[@a=1 or @b=2]`。
* 最高频的三条：`//*[@id="list"]//dt[2]/following-sibling::dd/a`（26）、
  `//*[text()="作者"]//text()`（22）、`//meta[@property='og:novel:author']/@content`（19）。

实现的就是这些，加上 `|` 并集和尾部的 `/@属性` `/text()` 取值器。分组
`(...)`、其它轴、字符串函数一律**报错**。

三条容易做错、写测试才逮住的：

- **`/` 开头是绝对路径，起点是文档不是当前元素。** `bookUrl` 那种逐元素
  求值的字段里写 `//meta[@property='og:image']/@content`，起点写成当前元素
  就一条都取不到。
- **位置谓词是「每个父节点各算各的」**：`/div/p[2]` 是「每个 div 的第 2 个 p」，
  不是「全部 p 里的第 2 个」。
- **`text()` 用直接文本子节点**，不是整棵子树的文本 —— 否则
  `//*[contains(text(),'状态')]` 会把 html/body/div 这些祖先全匹配上。

XPath 的求值结果是**元素下标**，尾部取值器交给 `Html::accessor` ——
和 CSS 那条路共用同一套取值逻辑，两边不会跑偏。

顺手逮到的一个真 bug：`literal_url`（把「展开后就是个地址」的规则按字面返回）
一开始把 `//` 也当协议相对地址收，于是**每条 `//` 开头的 XPath 都被原样当成
URL 返回了**——规则看着生效，值却是那串选择器本身。现在要求 `//` 后面得像主机名。

## 覆盖率

拿 3907 个真书源静态统计「按现在的实现应该能跑」（有搜索 + 完整的
搜索/目录/正文规则 + 不依赖没实现的能力）：

```
                     改动前    +JSON    +XPath
 启用的文本源          3678     3678      3678
 **应该能跑**         2226     2720      2943    ← 60% → 73% → 80%
 去重后的域名          1105     1318      1428
 剩余阻塞  jsonpath     567        0         0
           xpath        236      236         0
           aes           34       34        34
```

同一个统计脚本跑三遍（`survey_coverage.py`，开关翻 JSON 路径 / XPath 算不算
阻塞），所以这两个增量是可信的。

**动态**走通全链路是另一回事（站点会挂、会过期）：

| 夹具 | 走通 | 说明 |
|---|---|---|
| 基线（不用 JS） | 3 / 30 | 改动前后一致，没退化 |
| 基线（用 JS） | 2 / 24 | 同上 |
| 纯 JSON 源 | 2 / 50 | 改动前 0；「疯读小说」拿到 514 章 + 2473 字正文 |
| 纯 XPath 源 | 0 / 33 | **全部 33 个站都死了** |

XPath 那 33 个不可动态验证，所以验证靠**离线端到端测试**
（`tests/xpath_source.rs`，假站点 + 真实 HTML 形状，7 条）。抽查过一个：
`www.iwurexs.com` 已经 301 到 `4020xs.com`，落地页 8 KB、没有任何结果标记 ——
是站死了，不是 XPath 错了。

## 阅读页的两种模式（`m` 切换）

`阅读屏` 里的 `m` 在两种显示之间切：

| 模式 | 内容区看到什么 |
|---|---|
| **普通** | 正文段落，段落之间空行 |
| **隐蔽** | 生成出来的 TypeScript，正文在 `//` 注释里 |

隐蔽模式显示的就是 `.novel/reader.novel` 那份内容（同一份数据，不会脱节）。
`//` 注释行是正文给亮色，其余代码压暗 —— 一眼能从代码里认出小说，
但整屏看着就是代码。

隐蔽模式下**整屏只有那块代码**：

```
┌ reader.novel ──────────────────────────────────────────────┐
│/*                                                          │
│ *                                                          │
│export interface BufferState {                              │
│  retry?: number;                                           │
│// 他推开门，楼道里的声控灯亮了一下，又灭了。               │
└────────────────────────────────────────────────────────────┘
```

标题栏（书名/作者/进度/上次搜索）、标签栏、状态栏、快捷键提示**全都不画** ——
它们每一个都会出卖你。块标题换成文件名，像编辑器打开了一个 `reader.novel`。
**键位一个没变**，只是不画那些界面元素，所以功能不受影响。

隐藏分两档，规矩不同：

- **块注释**（文件头 `/** … */` 里的书名、章节名、书源名）—— 纯泄漏、
  没有阅读价值，所以**一直**抹掉。
- **行注释**（`//` 里的正文）—— 那是你正在读的东西，所以**闲置 15 秒**
  才抹；任何输入立刻显示回来。标记和行数保留，屏幕不跳、滚动位置还作数。

> 代价：状态栏也藏了，所以隐蔽模式下看不见失败信息。`self.status` 一直在，
> 按一下 `m` 回到普通模式就能看到。

模式**跟着 `state.json` 落盘**（这是个会跟人很久的偏好，不该只在内存里），
老的状态文件（没有 `mode` 字段）照常读得进来。

## 目录缓存

目录是「拉一次、之后很多次都要用」的东西：站点慢的时候每次打开一本书都要
等好几秒，而目录一天也变不了几章。所以缓到 `.novel/toc/`：

- **打开书时缓存优先** —— 命中就不发任何网络请求，秒开
- **有效期 7 天**，过期自动重拉
- **`R` 强制重拉**（目录屏和阅读屏都能按）—— 缓存是为了「不用每次都等」，
  不是「永远看不到新章节」，所以必须留一个明确的刷新键
- **状态栏会说**（`目录 327 章（缓存）`）—— 不说的话用户会奇怪为什么没有最新章节
- 缓存键是 `书源名 + 书 URL + 目录规则指纹`：改了 `ruleToc` 之后旧缓存自动失效
  （否则会读到按旧规则切出来的章名和链接）
- 缓存坏了/缺了/写不进去都当没有 —— **缓存绝不该让打开一本书失败**

指纹用自己写的 6 行 FNV-1a，不用 `DefaultHasher`：后者换个 rustc 版本哈希就变了，
缓存会集体失效（无害但很莫名）。

## 书架与章节记忆

书架在 `.novel/shelf.json`，和「当前界面状态」分开：

```json
{"books":[{"source":"鬼吹灯","name":"斗破苍穹.2","author":"柴老五",
           "url":"http://www.gdbzkz.la/doupocangqiong2/",
           "chapter":3,"title":"正文_第3章：他人眼中的废物",
           "chapters":327,"readAt":1789880036}]}
```

- **打开过的书自动进书架** —— 「之后还想接着读」是绝大多数情况，不该再收一道税
- **每读一章就记一次**（章号 + 标题 + 时间），书架按最近阅读倒序
- **重启后接着读**：启动后按 `Enter` 打开书架第一本，会跳回上次那一章
- **按 URL 认书**，不按书源下标 —— 书源列表会因为导入/删除重排，
  用下标当主键的话删一个源就会把别人的进度串到另一本书上
- 重新收藏同一本书**不会冲掉阅读进度**（进度是资产）

## 自测交互

`--script` 把一串按键喂给**真实的事件循环**，把界面打到 stdout。
存在的理由是「按键 → 排后台任务 → 收结果 → 重画」这条链以前只能人眼验，
而卡死、丢结果、退不出去都出在这里。

```bash
novel-tui --script '{down}{enter}nnp'          # 打开第二本、翻两章再回一章
novel-tui --script '{wait:8000}{down}{enter}'  # 等后台把搜索结果交回来
novel-tui --script '?' --trace                 # 每一帧都打出来
```

脚本语法：普通字符就是字符键；`{down}` `{enter}` `{esc}` `{pgup}` `{btab}`
`{ctrl-c}` 这类是特殊键；`{wait}` / `{wait:8000}` 是等待（**在线脚本必须用它**，
不然脚本会在结果到达前就把后面的键全按完）。

`crates/novel-tui/tests/interaction.rs` 里 17 条测试用的是同一套东西，
只是后台是假的（`Workers::for_test()` 把任务丢掉，测试在脚本的指定位置把
`Done::Search` / `Done::Toc` / `Done::Read` 塞回来），所以完全离线、确定性。
覆盖：翻章快捷键逐个、跳章输入校验、边界、在线全链路、自动进书架、
章节记忆跨重启、收藏增删、换书、书源导入/编辑/删除、失败提示、小终端。

### 「随机」但确定性

模板、标识符、块的位置都是随机挑的，但**种子取自（书名 + 章节标题）**，
所以同一章渲染出来逐字节一致：测试能断言，阅读页也不会在重抓时抖成另一个样子。

生成器保证（都有测试）：正文只出现在 `//` 注释里、每个声明名唯一
（重复声明 TS 直接编译不过）、花括号配平、不连着出两块同形状的代码。

## 交互设计评审

交互是**照着评审稿改的**，不是拍脑袋排的键位。完整规格在
[`docs/tui-interaction-design.md`](docs/tui-interaction-design.md)（862 行，
五屏的正常/空/加载/出错四态），静态稿在 `docs/tui-screens.html`。

评审抓到的**真 bug**（不是审美问题）：

- **全局键抢文本输入。** 原来 `q`/`S`/`b`/`o`/`r`/`1-9` 都是全局键，而搜索
  关键字框是**常驻输入焦点**（不是临时模式）。结果是在搜索框里敲小说名
  —— 名字里有 `q` 就直接退出应用、有 `b` 就收藏、有数字就开关书源。
  现在分发的优先级是 `Ctrl-C` → 帮助浮层 → 临时输入框 → **搜索关键字框**
  → 本屏命令，回归测试见 `typing_in_the_search_box_is_never_a_command`。
- ~~`q` 只在根书架退出~~ → **改回全局**（用户要求）：哪一屏都行。
  「搜索框里打 q 不能退出」那条仍然成立 —— 靠的是输入焦点优先级，不是屏作用域。
- **书源屏没筛选。** 默认集合几千个，没有筛选只能按住下键一页页翻。
  现在 `/` 筛选（名字或网址），标题给「匹配 M / 共 N」，`Ctrl-U` 清空。
- **光标该在显示列表里，不是源数组下标里。** 边筛边选的时候源下标会动，
  拿它当光标会让选中项乱跳；开关/编辑要**映射回**原始下标才对（有测试）。
- **书源三字段该是一个表单。** 原来 `e`/`u`/`s` 各开一个单字段输入框，
  要记三条键位、还得改一个退出来再改下一个。现在 `Enter` 进表单，
  Tab 换字段、Enter 一起保存、Esc 取消，改过东西要先提醒一次（脏数据保护）。
- **一屏一屏地走会迷路。** 加了面包屑画整条路径（`书架 › 搜索 “斗破” › 目录 · X`），
  谁进来就退回谁 —— 从搜索进的目录，`Esc` 回搜索而不是回书架。
- **选中态不能只靠颜色。** 现在选中行有 `>` 前缀**并且**反显：反显在纯文本
  导出里看不见，而只靠颜色区分对色觉障碍用户不成立。

用户实跑之后报上来的两个问题（都不是评审里的，是真用才发现的）：

- **搜索结果永远最多 20 条。** `Online::search` 只抓第 1 页再
  `take(HITS_PER_SOURCE=20)` —— 而 `crawl::search(key, page)` **本来就支持翻页**，
  只是没人调用。现在每个源翻到 10 页、总数上限 300，实测同一个搜索从
  「20 条」变成「49~100 条」。
- **目录每次都实时拉。** 加了 `.novel/toc/` 缓存（见下）。

写这个缓存时自己踩的坑：`dir()` 被调了两次，缓存写进了
`.novel/toc/toc/` —— 文件确实写了、行为看着完全正常，但**永远读不中**，
等于没有缓存。这种 bug 只有真跑一遍并去看磁盘才会发现，测试写「存了能读回来」
才抓得住（已加 `the_cache_dir_is_not_doubled`）。

实现时踩到、也修掉的自己写的 bug：加面包屑那一行时忘了把屏往下挪一格，
五屏全被挤成 1 行高 —— 阅读屏只剩一条上边框，被测试当场抓到。

### 测试语料抓到的两个崩溃

语料测试值回票价了 —— 它抓到两个手写测试永远覆盖不到的 bug：

1. **死循环烧光内存**。`{{$.chapter_id}}` 是常见写法（JSON 路径内嵌），
   而词法分析器扫标识符时从当前字符起步，`$` 不在「标识符续接字符」集合里，
   于是指针原地不动，每轮往 token 列表里塞一个 `Ident`，直到申请 64 GB 内存失败。
   修法：从 `i + 1` 起步，保证每轮至少前进一个字符。
2. **按字节切中文**。前缀判断写成 `s[..prefix.len()]`，
   `text.下一页@href` 的第 6 个字节落在「下」字中间，直接 panic。
   修法：`str::get`（越界/非边界返回 `None`）。

参考实现是 Android 的「阅读 Sigma」(legado) —— 复用它的书源 JSON schema
